# terraform-provider-openmetadata

Terraform provider for OpenMetadata, built on `terraform-plugin-framework`.

- Go module: `github.com/gr8-toolkit/terraform-provider-openmetadata` (Go version in `go.mod`; all builds use `CGO_ENABLED=0`)
- Registry address: `registry.terraform.io/gr8-toolkit/openmetadata`
- Provider type name `openmetadata` → every resource and data source is `openmetadata_*`
- Dependency versions: see `go.mod`. `terraform-plugin-docs` is a tools-only dependency (`tools/tools.go`).

Area-specific guidance lives in nested files that load when you work there:

- `internal/resources/CLAUDE.md` — resource file layout, schema/JSON helpers, CRUD, write-only fields
- `internal/provider/CLAUDE.md` — acceptance test patterns and the in-memory fake server

## Architecture

```text
main.go                         entry point; version/commit injected by goreleaser ldflags;
                                holds the //go:generate directive for tfplugindocs
internal/provider/provider.go   schema (host + token), Configure() builds + pings the client,
                                Resources() and DataSources() register everything
internal/client/client.go       thin net/http wrapper (no external HTTP library), 30s timeout,
                                Bearer auth, tflog logging
internal/resources/             one file per resource, plus common.go (shared helpers)
internal/datasources/           one file per data source
internal/provider/              provider code and ALL tests (provider_test.go = shared infra)
examples/                       HCL consumed by tfplugindocs
docs/                           AUTO-GENERATED — never edit directly
```

`provider.go` is the source of truth for what is registered; read `Resources()` / `DataSources()`
instead of trusting any list here. Most entities have both a resource and a data source, with a
resource file, data source file, `<name>_resource_test.go` and `<name>_data_source_test.go`.

## Provider authentication

Optional `host` and `token`, resolved from explicit config first, then `OPENMETADATA_HOST` /
`OPENMETADATA_TOKEN`. `Configure()` errors if either is empty, then calls `client.Ping()` before
handing `*client.Client` to resources and data sources via `ProviderData`.

## Client API (`internal/client/client.go`)

| Method | HTTP | Notes |
|---|---|---|
| `CreateOrUpdate(ctx, collection, body)` | `PUT /api/v1/{collection}` | Idempotent — used for both Create and Update |
| `GetByName(ctx, collection, fqn, fields)` | `GET .../name/{fqn}?fields=...` | Returns `nil, nil` on 404 |
| `GetByID(ctx, collection, id, fields)` | `GET .../{id}?fields=...` | Returns `nil, nil` on 404 |
| `Delete(ctx, collection, id, hardDelete)` | `DELETE .../{id}?hardDelete=true&recursive=true` | Always hard-deletes in practice |
| `Ping(ctx)` | `GET /api/v1/system/version` | Connectivity check in `Configure()` |

HTTP errors ≥ 400 are returned as `*client.APIError{Code, Message, ResponseHTTPCode}`.

## Commands

```bash
make build   # compile — do this before committing
make test    # unit tests, no live OpenMetadata needed
make lint    # golangci-lint run ./...
make fmt     # go fmt ./...
make docs    # regenerate docs/ via tfplugindocs (after any schema or example change)
make deps    # go mod tidy
make install # copy the binary into ~/.terraform.d/plugins for manual testing
```

Gate before every commit — all four must pass, CI runs them in this order:

```bash
make fmt && make lint && make build && make test
```

Pre-commit also runs `golangci-lint` on the whole module (e.g. unused helpers in `_test.go` files
fail it), so lint before committing even if only tests changed.

Only OpenMetadata 2.x is supported (1.x was dropped); the supported versions are listed in
`docker/test/versions`, and the first line is the default.

Acceptance tests (need Docker or a running OpenMetadata):

```bash
make testacc                      # docker-compose lifecycle, ~20 min, 8 GB RAM
make testacc OM_VERSION=2.0.3     # a specific OM version
make testacc-all                  # every version in docker/test/versions
export OPENMETADATA_HOST=http://localhost:8585 OPENMETADATA_TOKEN=<jwt-admin-token>
make testacc-external             # against an instance you already run
```

## Documentation

`docs/` is generated by `tfplugindocs`. **Never edit it by hand.** To change docs:

1. Edit the `Description` fields in the resource/data source `Schema()`, or
2. Edit `examples/resources/openmetadata_<name>/resource.tf` /
   `examples/data-sources/openmetadata_<name>/data-source.tf`.
3. Run `make docs` and commit the source change together with the regenerated `docs/`.

## Adding a resource (checklist)

To add a new resource and data source, follow the codegen skill in `.github/skills/codegen/SKILL.md`
(callable as `/codegen` when symlinked into `.claude/skills/`). It expands this checklist:

1. `internal/resources/<entity>.go` — follow `internal/resources/CLAUDE.md`.
2. Register it in `internal/provider/provider.go` → `Resources()`.
3. `internal/provider/<entity>_resource_test.go` — CI fails if a resource has no test file.
4. `examples/resources/openmetadata_<entity>/resource.tf` — realistic HCL.
5. For a data source: `internal/datasources/<entity>.go`, register in `DataSources()`,
   `internal/provider/<entity>_data_source_test.go`, and
   `examples/data-sources/openmetadata_<entity>/data-source.tf`.
6. Add the README rows (resource table, data source list), then `make docs` and the commit gate above.

## Git and PR conventions

- Open an issue before writing code for new resources or non-trivial changes; bug fixes and doc
  corrections can go straight to a PR.
- Branch from `main`. PR titles and commits use Conventional Commits (`feat:`, `fix:`, `chore:`,
  `docs:`), under 72 characters, imperative, no trailing period. The body explains *why*.
- Squash to **one commit** before requesting review, and again after each round of feedback.
- Every PR needs passing CI (lint, unit tests, acceptance tests). A maintainer merges.

## Releases (maintainers only)

Tag `vMAJOR.MINOR.PATCH` on `main` (`git tag vX.Y.Z && git push origin vX.Y.Z`). `release.yml` runs
GoReleaser: cross-platform ZIPs, SHA256SUMS, GPG-signed checksums, GitHub release and Terraform
Registry publish. The changelog is **not** auto-generated — write release notes on the GitHub release.
