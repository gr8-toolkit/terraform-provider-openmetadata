# Contributing Workflow

## Before You Start

Open a GitHub issue before writing code for new resources or non-trivial changes.
Bug fixes and doc corrections can go straight to a PR.

## Daily Development Commands

```bash
make build   # Compile — always do this before committing
make test    # Unit tests, no live OpenMetadata instance needed
make lint    # golangci-lint run ./...
make fmt     # go fmt ./...
make docs    # Regenerate docs/ via tfplugindocs (after any schema or example change)
make deps    # go mod tidy
```

Gate before every commit:

```bash
make fmt && make lint && make build && make test
```

All four must pass. CI runs them in this order and will fail the PR if any step fails.

## Acceptance Tests

```bash
# Full docker-compose lifecycle — allow ~20 min and 8 GB RAM
make testacc

# Against a specific OM version
make testacc OM_VERSION=2.0.3

# Against all versions in docker/test/versions (CI matrix)
make testacc-all

# Against an external instance you already have running
export OPENMETADATA_HOST=http://localhost:8585
export OPENMETADATA_TOKEN=<jwt-admin-token>
make testacc-external
```

CI runs acceptance tests against the version matrix from `docker/test/versions`.
A fork PR needs a maintainer to approve the acceptance test run.

## Pull Request Conventions

- Branch from `main`. Fork the repo if you are outside the org; branch directly if you have write access.
- Title format: **Conventional Commits** — `feat:`, `fix:`, `chore:`, `docs:`. Keep it under 72 characters.
- Squash to **one commit** before requesting review, and again after incorporating each round of feedback.
- Every PR needs passing CI (lint + unit tests + acceptance tests).
- A maintainer merges; outside contributors cannot merge their own PRs.

## Commit Message Format

```text
feat: add openmetadata_pipeline_service resource

Implements the full CRUD + import lifecycle for pipeline services
(OM collection: services/pipelineServices).

- Adds internal/resources/pipeline_service.go
- Registers NewPipelineServiceResource in provider.go
- Adds acceptance tests covering create/update/import
- Adds examples/resources/openmetadata_pipeline_service/resource.tf
- Regenerates docs/
```

First line: `<type>: <what changed>` (imperative mood, no period).
Body (optional): explain *why*, not *what* — the diff shows what.

## Documentation

`docs/` is entirely auto-generated by `tfplugindocs`. **Never edit it directly.**

To update docs:

1. Edit the `Description` fields in `Schema()` inside the resource file, or
2. Edit `examples/resources/openmetadata_<name>/resource.tf`.
3. Run `make docs` — this regenerates `docs/resources/<name>.md`.
4. Commit both the source change and the regenerated `docs/` output.

## Adding a New Resource — Quick Reference

1. Create `internal/resources/<entity>.go` (follow the file structure in `resource-development.md`).
2. Register in `internal/provider/provider.go` → `Resources()`.
3. Create `internal/provider/<entity>_resource_test.go` — CI fails if a resource has no test.
4. Create `examples/resources/openmetadata_<entity>/resource.tf`.
5. Run `make docs` to regenerate `docs/resources/<entity>.md`.
6. Run `make fmt && make lint && make build && make test`.

## Local Install for Manual Testing

```bash
make install
# Copies the binary to:
# ~/.terraform.d/plugins/registry.terraform.io/gr8-toolkit/openmetadata/<version>/<os>_<arch>/
```

Then reference it in a local Terraform config:

```hcl
terraform {
  required_providers {
    openmetadata = {
      source  = "registry.terraform.io/gr8-toolkit/openmetadata"
      version = "~> 0"
    }
  }
}
```

## Release Process (Maintainers Only)

1. Ensure `main` is clean and all CI checks pass.
2. Tag the commit: `git tag vX.Y.Z && git push origin vX.Y.Z`
3. The `release.yml` GitHub Actions workflow triggers GoReleaser automatically:
   - Builds cross-platform binaries (linux/windows/freebsd/darwin × amd64/arm64/386/arm).
   - Packages as ZIP archives named `{project}_{version}_{os}_{arch}.zip`.
   - Generates SHA256SUMS and `terraform-registry-manifest.json`.
   - GPG-signs the checksum file with the gr8-toolkit key (`GPG_FINGERPRINT` secret).
   - Publishes to the GitHub release and the Terraform Registry.
4. Changelog is **not** auto-generated — write release notes manually on the GitHub release.

Version format: `vMAJOR.MINOR.PATCH` — semantic versioning, tagged on `main` only.
